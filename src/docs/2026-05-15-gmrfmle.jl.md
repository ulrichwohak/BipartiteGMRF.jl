# GMRF Estimation Library — Revised Design Plan

A design document for spinning the GMRF estimation routines in `src/estimate/`
out into a stand-alone, open-source Julia package. The new folder/repo will be
created separately; this document is the specification a contributor or the user
can follow when building it.

This revision incorporates the main architectural changes needed for a
registered-quality library:

- distinguish the statistical prior/model from the numerical solver;
- preserve original firm/worker IDs and index maps in the prepared problem;
- expose prior and posterior decompositions deliberately;
- avoid porting project scripts verbatim where library refactoring is required;
- make unsupported model/solver/weighting combinations explicit.

## 1. Purpose and Non-Goals

**Purpose.** Provide a clean Julia interface for fitting bipartite-graph GMRF
random-effects models with rho-coupled left/right node effects, plus prior and
posterior variance decomposition and covariance-block extraction. For an
observed edge `e` between firm `f(e)` and worker `w(e)`, the baseline model is:

```text
y_e = a_{f(e)} + z_{w(e)} + epsilon_e
```

with `(a, z)` jointly Gaussian on the bipartite graph and parametrized by
`(rho, sigma_a, sigma_z, sigma_epsilon)`.

**In scope.**

- Normalized and unnormalized bipartite GMRF prior specifications from
  `gmrfmle.jl`.
- The variance-stable precision model from `gmrfvs.jl`, treated as a distinct
  prior/model variant rather than merely a solver.
- Numerical solvers for the marginal likelihood:
  `HutchSLQ` and `ExactCholesky`, subject to capability checks.
- Prior variance decomposition.
- Posterior expected variance decomposition.
- Prior and posterior covariance block extraction.
- DataFrame-in, typed-struct-out API with configurable column names.
- Reproducibility through explicit seeding and local RNG objects.

**Out of scope.**

- File I/O in the library API. No Parquet/CSV/JSON readers or writers; callers
  provide a table-like object, initially a `DataFrame`.
- Plotting and report rendering.
- Distance-decay and degree-stratified analysis modules.
- AKM / `VarianceComponentsHDFE` comparison glue.
- Makefile orchestration, CLI argument parsing, project-specific output paths,
  and `estimates.txt` parsing/writing.

## 2. Working Name

**Recommended working name:** `BipartiteGMRF.jl`.

Alternatives:

| Name | Tradeoff |
|---|---|
| `BipartiteGMRF.jl` | Descriptive of model class; neutral on application domain. |
| `MatchedGMRF.jl` | Good for matched-data applications; slightly narrower. |
| `EmployerEmployeeGMRF.jl` | Informative for labor applications; too domain-specific. |
| `AkmRandomEffects.jl` | Connects to AKM literature; risks confusion with AKM fixed effects. |
| `MobilityGMRF.jl` | Evokes worker mobility networks; narrower than the model warrants. |

The General-registry name can remain open until the first external workflow has
been tested.

## 3. Design Goals

- **Separate model from solver.** A precision-model object describes `Q`; a
  solver object describes how to optimize/evaluate the likelihood.
- **Single-call high-level entry.** `gmrf_mle(df; ...)` covers the typical case.
- **Two-step lower-level API.** Users can build a `GMRFProblem` once and call
  `solve(problem, solver; ...)` repeatedly.
- **Configurable column names.** Defaults are `:firm_id`, `:worker_id`, and
  `:y`; project-specific names are not hard-coded.
- **Stable ID metadata.** `GMRFProblem` stores original firm/worker ID vectors
  and lookup maps, so covariance extraction and downstream joins are reliable.
- **Typed results.** Public API returns `GMRFResult`, `VarianceDecomposition`,
  and `CovarianceBlock`, not unstructured `NamedTuple`s.
- **No project side effects.** No `Pkg.activate(".")`, no path parsing, no
  output writing, and no global `BLAS.set_num_threads` inside library load.
- **Reproducibility.** Randomness is controlled by explicit `seed` or `rng`
  kwargs; stochastic likelihood and decomposition streams are separated.
- **Light dependency footprint.** Keep I/O, plotting, and domain-specific
  econometrics packages outside the library.

## 4. Public API Sketch

These are signatures and usage sketches, not final implementations.

### High-Level Entry Point

```julia
using BipartiteGMRF, DataFrames

result = gmrf_mle(
    df;
    outcome      = :y,
    firm_id      = :firm_id,
    worker_id    = :worker_id,
    prior        = NormalizedPrior(),
    solver       = ExactCholesky(),
    weighting    = Weighting(),
    decompose    = 200,          # prior decomposition probes, or false/nothing
    fix_rho      = nothing,      # or Float64 in (-0.99, 0.99)
    max_degree   = nothing,
    standardize  = true,
    on_missing   = :drop,        # :drop | :error
    seed         = 42,
    verbose      = true,
)
```

### Prior / Precision Model Constructors

```julia
NormalizedPrior(; adjacency = :degree, prior_adjacency = :binary)
UnnormalizedPrior(; prior_adjacency = :binary)
SpectralPrior(; prior_adjacency = :binary)
VarianceStablePrior()
```

Notes:

- `NormalizedPrior(adjacency=:degree)` corresponds to the degree-normalized
  default in `gmrfmle.jl`.
- `UnnormalizedPrior()` corresponds to the paper-style `D - rho*A` precision.
- `SpectralPrior()` corresponds to the spectral normalization path.
- `VarianceStablePrior()` corresponds to `gmrfvs.jl` and is a different
  precision model, not just a different optimizer.

### Solver Constructors

```julia
HutchSLQ(;
    logdet_probes = 30,
    lanczos_iters = 30,
    cg_tol        = 1e-6,
    cg_maxiter    = 700,
    optim_iters   = 1000,
)

ExactCholesky(;
    optim_iters = 200,
    polish      = true,
    autodiff    = :finitediff,
)
```

`ExactCholesky` should default to finite differences unless sparse CHOLMOD
factorization has been verified with a stronger AD path. Forward-mode AD should
be treated as experimental.

### Weighting Bundle

```julia
Weighting(;
    observations = :raw,     # :raw | :edge | :effective
    rho_eps      = nothing,  # Float64 or :estimate, only for :effective
    target       = :estimation,  # :estimation | :personyear | :edge
)
```

The prior adjacency choice belongs to the prior model, not the observation
weighting bundle.

### Two-Step API

```julia
problem = GMRFProblem(
    df;
    outcome     = :y,
    firm_id     = :firm_id,
    worker_id   = :worker_id,
    prior       = NormalizedPrior(),
    weighting   = Weighting(),
    max_degree  = nothing,
    standardize = true,
    on_missing  = :drop,
)

result_exact = solve(problem, ExactCholesky(); decompose=200, seed=42)
result_hutch = solve(problem, HutchSLQ(); decompose=200, seed=42)
```

### Result Type and Accessors

Prefer ASCII field names. Unicode aliases can be supported later through
`getproperty` or pretty display, but downstream code should not need them.

```julia
result.rho
result.sigma_a
result.sigma_z
result.sigma_epsilon
result.nll
result.converged
result.iterations
result.obj_evals
result.optimization_time
result.prior_decomposition
result.posterior_decomposition   # nothing unless explicitly requested/computed
result.problem
result.prior
result.solver

coef(result)          # NamedTuple
nll(result)
converged(result)
prior_decomposition(result)
```

### Prior and Posterior Decomposition

The high-level `decompose=N` argument computes the **prior** variance
decomposition only. Posterior decomposition is conceptually distinct and should
be opt-in:

```julia
prior_decomp = prior_decomposition(result)

post_decomp = posterior_decomposition(
    result;
    probes = 200,
    seed   = 42,
)
```

Both return a `VarianceDecomposition` with:

```julia
decomp.V_firm
decomp.V_worker
decomp.V_cross
decomp.V_epsilon
decomp.V_total
decomp.n_probes
decomp.target          # :estimation | :personyear | :edge
decomp.kind            # :prior | :posterior
decomp.method          # :hutch_pcg | :hutch_cholesky
decomp.pcg_converged   # Int or nothing
```

### Covariance Extraction

```julia
prior_op     = prior_covariance(result)
posterior_op = posterior_covariance(result)

firm_block = cov_block(prior_op; firms = firm_ids)
joint_block = cov_block(posterior_op; firms = firm_ids, workers = worker_ids)
rect_block = cov_block(prior_op; row_firms = firm_ids, col_workers = worker_ids)
```

`cov_block` should return a `CovarianceBlock`, not a bare matrix:

```julia
block.matrix
block.rows
block.cols
block.kind       # :prior | :posterior
block.units      # :standardized | :original
```

`CovarianceOperator` owns or caches the relevant sparse factorization and uses
the ID maps in `GMRFProblem` to resolve entity IDs.

## 5. Capability Matrix

Unsupported combinations should throw clear `ArgumentError`s before fitting.

| Prior model | HutchSLQ | ExactCholesky | Notes |
|---|---:|---:|---|
| `NormalizedPrior(adjacency=:degree)` | yes | yes | Main default. |
| `SpectralPrior()` | yes | later / optional | Exact path needs implementation parity. |
| `UnnormalizedPrior()` | yes | yes | Uses degree-weighted diagonal. |
| `VarianceStablePrior()` | yes | later / optional | Different `Q`; not just a solver. |

Observation weighting support should also be explicit:

| Observation weighting | Normalized/Unnormalized | VarianceStable |
|---|---:|---:|
| `:raw` | yes | yes |
| `:edge` | yes | later / optional |
| `:effective` with fixed `rho_eps` | yes | later / optional |
| `:effective` with estimated `rho_eps` | yes | later / optional |

The first release can support a smaller matrix, but it must fail loudly for
unsupported combinations.

## 7. Type Hierarchy

```julia
abstract type AbstractGMRFPrior end
abstract type AbstractGMRFSolver end

struct NormalizedPrior <: AbstractGMRFPrior
    adjacency::Symbol          # :degree
    prior_adjacency::Symbol    # :binary | :counts
end

struct SpectralPrior <: AbstractGMRFPrior
    prior_adjacency::Symbol
end

struct UnnormalizedPrior <: AbstractGMRFPrior
    prior_adjacency::Symbol
end

struct VarianceStablePrior <: AbstractGMRFPrior
end

struct Weighting
    observations::Symbol       # :raw | :edge | :effective
    rho_eps::Union{Nothing,Float64,Symbol}
    target::Symbol             # :estimation | :personyear | :edge
end

struct GMRFProblem
    y::Vector{Float64}
    projected_y::Vector{Float64}
    VtV::SparseMatrixCSC{Float64,Int}
    A_prior::SparseMatrixCSC{Float64,Int}
    A_obs::SparseMatrixCSC{Float64,Int}
    d_f::Vector{Float64}
    d_w::Vector{Float64}
    cnt_f::Vector{Float64}
    cnt_w::Vector{Float64}
    firm_ids::Vector
    worker_ids::Vector
    firm_to_index::Dict
    worker_to_index::Dict
    N_firms::Int
    N_workers::Int
    K::Int
    y_mean::Float64
    y_std::Float64
    standardize::Bool
    prior::AbstractGMRFPrior
    weighting::Weighting
    metadata::NamedTuple
end

struct HutchSLQ <: AbstractGMRFSolver
    logdet_probes::Int
    lanczos_iters::Int
    cg_tol::Float64
    cg_maxiter::Int
    optim_iters::Int
end

struct ExactCholesky <: AbstractGMRFSolver
    optim_iters::Int
    polish::Bool
    autodiff::Symbol
end

struct GMRFResult
    rho::Float64
    sigma_a::Float64
    sigma_z::Float64
    sigma_epsilon::Float64
    rho_eps::Union{Nothing,Float64}
    nll::Float64
    converged::Bool
    iterations::Int
    obj_evals::Int
    optimization_time::Float64
    prior_decomposition::Union{VarianceDecomposition,Nothing}
    posterior_decomposition::Union{VarianceDecomposition,Nothing}
    problem::GMRFProblem
    prior::AbstractGMRFPrior
    solver::AbstractGMRFSolver
end

struct VarianceDecomposition
    V_firm::Float64
    V_worker::Float64
    V_cross::Float64
    V_epsilon::Float64
    V_total::Float64
    n_probes::Int
    target::Symbol
    kind::Symbol
    method::Symbol
    pcg_converged::Union{Nothing,Int}
end

struct CovarianceOperator
    kind::Symbol
    factor
    result::GMRFResult
    units::Symbol
end

struct CovarianceBlock
    matrix::Matrix{Float64}
    rows::Vector
    cols::Vector
    kind::Symbol
    units::Symbol
end
```

The concrete field types for ID vectors and maps can be parameterized later to
avoid type instability without overcomplicating the first implementation.

## 9. Dependencies

**Required.**

- `DataFrames` initially, for the DataFrame input constructor.
- `Optim` for Nelder-Mead and L-BFGS/finite-difference paths.
- `FiniteDiff` for finite-difference diagnostics and exact-solver optimization.
- `ADTypes` only if retained for backend selection; otherwise defer until AD is
  actually supported.
- Stdlibs: `SparseArrays`, `LinearAlgebra`, `Statistics`, `Random`, `Printf`,
  `Logging`.

**Dropped relative to the current project.**

- `Parquet2`, `CSV`, `JSON` in the library core.
- `Plots` / `Makie`.
- `Kezdi`.
- `Graphs`, unless later functionality truly needs it.

**Suggested compat.**

```toml

```

**Test-only extras.** `Test`, `StableRNGs`.

## 10. Test Strategy

- **Synthetic fixture, not Parquet.** A
  `synthetic_bipartite(; n_firms, n_workers, edges_per_worker, sigma_a,
  sigma_z, rho, sigma_epsilon, seed)` generator returns a DataFrame and
  ground-truth parameters.
- **Preparation tests.** Verify missing handling, standardization, configurable
  columns, ID order, index maps, duplicate edge collapse, and all observation
  weighting modes.
- **Operator tests.** `QOp`, `QOpVS`, and `MOp` match dense reference matrices
  on toy graphs for all supported prior models.
- **PCG tests.** Solutions match dense backslash within tolerance and report
  non-convergence cleanly.
- **SLQ tests.** Log-determinant estimates are within Monte Carlo tolerance of
  dense `logdet` on small SPD matrices.
- **Solver tests.** Exact and stochastic solvers agree on small problems within
  stochastic tolerance. Parameter recovery should be checked only with generous
  tolerances because small GMRF samples can have flat likelihoods.
- **Capability tests.** Unsupported prior/solver/weighting combinations throw
  clear errors.
- **Decomposition tests.** Components sum to total within numerical tolerance
  for prior and posterior decompositions and for all supported targets.
- **Covariance tests.** `cov_block` matches selected blocks of `inv(Matrix(Q))`
  and `inv(Matrix(M))` on toy graphs, including rectangular firm-worker blocks.
- **Integration test.** Synthetic data -> `GMRFProblem` -> fit -> prior
  decomposition -> posterior decomposition -> covariance block.

## 12. Migration and Coexistence with Current Project

This library work should not initially change the existing project scripts.
After the library works:

1. Add `BipartiteGMRF` to the project via `Pkg.develop`.
2. Convert `gmrfmle.jl`, `gmrfmle_exact.jl`, and `gmrfvs.jl` into thin CLI
   wrappers: parse args, read Parquet, call the library, write `estimates.txt`.
3. Convert covariance extraction scripts into wrappers around
   `prior_covariance`, `posterior_covariance`, and `cov_block`.
4. Keep distance-decay, AKM comparison, and reporting code in the application
   repo.
5. Migrate pure algorithm tests to the library; keep project I/O and
   reproducibility tests in the application repo.

## 13. Implementation Phases

1. **Skeleton.** Create `Project.toml`, module file, basic type stubs, empty
   tests, and CI.
2. **Data preparation.** Implement `GMRFProblem` with configurable columns,
   stable ID maps, standardization, missing handling, max-degree filtering, and
   observation weights.
3. **Prior models and operators.** Implement normalized, spectral,
   unnormalized, and variance-stable `Q` operators plus `M = Q + lambda V'V`.
4. **Linear algebra.** Port PCG and SLQ using local RNGs and typed workspaces.
5. **Exact solver.** Implement `ExactCholesky` for supported prior models,
   finite-difference optimization, and clear failure modes.
6. **Hutch/SLQ solver.** Implement stochastic likelihood evaluation and
   Nelder-Mead optimization around `GMRFProblem`.
7. **Public API.** Implement `gmrf_mle`, `solve`, accessors, and `Base.show`.
8. **Prior decomposition.** Implement `prior_decomposition` and `decompose=N`.
9. **Posterior decomposition.** Implement explicit
   `posterior_decomposition(result; probes, seed)`.
10. **Covariance extraction.** Implement `CovarianceOperator` and
    `CovarianceBlock` with ID resolution and batched solves.
11. **Documentation.** Add README examples and Documenter pages.
12. **Open-source readiness.** Add license, citation, CI badges, CompatHelper,
    TagBot, and registration checklist.

## 14. Open Decisions

1. **Final package name.** Default: `BipartiteGMRF.jl`.
2. **Default solver.** Recommendation: `ExactCholesky()` for moderate sparse
   graphs because it is deterministic; document when to switch to `HutchSLQ()`.
3. **Default prior.** Recommendation: `NormalizedPrior(adjacency=:degree,
   prior_adjacency=:binary)`.
4. **Outcome standardization.** Default: `standardize=true`.
5. **Missing outcome handling.** Default: `on_missing=:drop`, not silent `NaN`
   propagation.
6. **AD support.** Keep `ExactCholesky(autodiff=:finitediff)` until a tested AD
   path exists for sparse Cholesky.
7. **Unicode aliases.** Keep ASCII fields public; optionally add Unicode
   display/accessors later.
8. **Table input generality.** Start with `DataFrame`; later accept any
   Tables.jl-compatible input if useful.
9. **Threading.** Do not mutate global BLAS thread settings in the library.
   Expose performance advice in docs instead.
